# 浮光语义氛围

## 背景

- 创建日期：2026-08-09
- 功能标识：`semantic-glow`
- 需求来源：飞书产品定义《浮光》（文档 `DLqtdJAgnoZWeWxA7HkcgQwUn0f`，读取版本 revision 8）。
- 当前任务卡在 `TaskListSection` 内直接按时间映射 `DDLStatus`，未形成可复用领域规则；未接入的 `HomeFocusPanel` 又重复计算风险，列表、摘要与未来顶部氛围无法保证同源。
- 分类色和品牌强调色已经各有通路，但缺少独立的状态语义契约与页面级聚合结果。

## 目标

- 建立单条任务的统一语义状态：`active / nearDue / overdue / completed / abandoned`，严格按放弃、完成、逾期、临期、正常的顺序判定。
- 建立当前页面可见范围的 `SemanticSnapshot`，由同一份筛选结果同时驱动任务卡状态和顶部 tone。
- 任务页按 `danger > warning > accent > success` 聚合；习惯页仅在存在可见习惯且完成率为 100% 时为 `success`，其他情况为 `accent`。
- 建立与分类色隔离、跟随用户 indicator 风格的 `SemanticPalette`，覆盖 `accent / success / warning / danger / calm / neutral` 六种 tone。
- 在 HarmonyOS 应用根层接入可滚动收缩的 `SemanticTopAtmosphere`；滚动路径只更新进度，不重复读取仓储或重算业务状态。
- 清单语义 tone 通过根级可观察字符串状态发布，避免跨多层自定义组件回调在冷启动或异步刷新时丢失更新。
- 让任务卡只消费已决策的语义状态与进度；分类仅保留徽标身份表达。
- 用 ArkTS 单元测试固定状态优先级、24 小时边界、无效截止时间和页面聚合规则。

## 非目标

- 不修改 KMP 持久化、数据库结构、任务状态机或同步协议。
- 不将用户品牌强调色或分类色开放为语义状态色；普通任务首页使用当前 indicator 风格的进行中色。
- 不在本轮实现“幻彩”装饰模式或新增外观设置入口。
- 不改造搜索页、归档页和小组件的业务内容；首版范围是根级顶部氛围及主页任务/习惯语义输入。
- 不继续扩张未接入且已接近规模上限的 `HomeFocusPanel.ets`；其重复语义逻辑不作为新功能依赖。

## 用户场景

1. 用户打开任务页时，顶部氛围立即表达当前筛选范围内最高风险：有逾期为红橙、仅有临期为橙黄、正常待推进为蓝、没有进行中任务为绿薄荷。
2. 用户切换分类筛选后，列表、统计和顶部 tone 使用同一批可见任务同步更新，不受被过滤任务影响。
3. 用户完成、恢复或放弃一项任务后，卡片状态和顶部 tone 同步变化；已完成或已放弃任务不会被过期时间覆盖。
4. 用户切到习惯页时，当天可见习惯全部完成才显示 success；无可见习惯或尚未全部完成保持 accent。
5. 用户切换分类颜色时，导航和分类徽标可以变化，但状态表达不受影响；切换 indicator 风格时，任务卡与顶部浮光同步换色。
6. 用户滚动列表时，顶部氛围保持整屏纵向染色并平滑减弱，颜色从顶部一直渐隐到屏幕底部，不出现横向裁切线，也不触发逐帧业务查询。

## 验收标准

- 放弃与放弃归档优先于完成、逾期和临期，并映射为灰色 `abandoned`；完成与完成归档优先于时间风险，并映射为绿色 `completed`。
- 进行中任务：截止时间早于当前时间为 `overdue`；截止时间在未来且不超过 24 小时为 `nearDue`；其他或截止时间不可解析为 `active`。
- 页面任务快照仅统计当前分类筛选后的可见任务：有逾期为 `danger`，否则有临期为 `warning`，否则仍有进行中任务为 `accent`，否则为 `success`。
- 页面习惯快照基于当前分类、搜索和日期对应的可见习惯：数量大于 0 且全部完成为 `success`，其他情况为 `accent`。
- 任务卡状态和顶部氛围在创建、编辑、完成、恢复、放弃、筛选变化及同步刷新后消费同一轮决策结果，无可见先后不一致。
- 任务卡状态底色与进度只来自语义 palette；分类图标和文字只影响徽标本身。
- `SemanticTopAtmosphere` 只接收 tone、scrollProgress 和 colorMode；滚动进度限制在 `0...1`，浮光保持整屏高度并在滚动时降低整体强度，底部透明淡出。
- 根导航与各主 Tab 的导航宿主背景必须透明，页面卡片仍保持原有材质与背景，确保最外层浮光能够透出且不覆盖交互。
- 四种主页 tone 直接复用当前 indicator 风格及其浅色/深色资源：`accent / success / warning / danger` 分别对应 `undergo / completed / near / passed`。
- tone 切换使用约 240ms 缓动，滚动收缩使用约 160ms 缓动；滚动回调不读取仓储、不解析任务时间。
- 领域 resolver 和聚合 resolver 有自动化单测；规格校验、1000 行扫描和一次显式 `DEVECO_HOME` 的统一构建通过。

## 风险与约束

- ArkTS 不得按通用 TypeScript 写法使用动态对象、结构化类型或不受支持的集合表达；实现前必须加载 `arkts-grammar-standards`，UI 组件同时加载 `arkui-knowledge`。
- `MainHomePage.ets`、`HomeFocusPanel.ets` 已接近或超过 1000 物理行，接线必须最小化；新增职责放入 `common/semantic` 和 `pages/components/semantic`。
- 当前大文件扫描的仓库既有超限为 `SearchPage.ets`（1100 有效行）和 `DatabaseHelper.ets`（1083 有效行）；第三方 `oh_modules` 另有 3 个超限文件。本功能不修改这些文件，也不申请新的超限逃逸。
- 顶部氛围需置于列表与导航内容之后且不拦截点击；HDS 导航自身的背景和安全区行为可能影响可见性，需要最终真机/模拟器视觉回归。
- 当前筛选状态由列表组件持有，因此使用显式快照回调把已过滤结果传给主页；不得由主页再次全量查询并自行过滤。
- 24 小时边界基于毫秒差判断；状态只在数据变更、筛选变化、页面重新出现或定时边界刷新时重算，不能放入滚动逐帧路径。

## 实现结果

- 已落地独立的语义 contract、任务状态 resolver、页面 tone resolver 与 indicator 驱动的 palette；品牌强调色和分类色没有进入语义决策链。
- 任务与习惯列表均在当前筛选结果形成后生成完整快照；主页保存两份快照，分段切换只选择对应快照，滚动只更新归一化进度。
- 已接入根级线性渐变、双径向光晕和底部透明淡出；任务卡消费统一状态判定并保留用户可切换的 indicator palette，分类徽标继续使用分类身份色。
- resolver 自动化测试已隔离运行通过，主应用 HAP 构建通过，规格与大文件扫描通过。
- 模拟器/真机上的浅色、深色、六 tone、三档滚动和动态状态切换仍需目视回归，当前规格不将其标记为已验证。

## 修订：根级统一浮光

- 任务卡的状态 indicator 继续服从用户选择的 indicator 风格；语义 resolver 负责状态判定，但不得用固定 palette 覆盖卡片的主题 indicator 颜色。
- 清单顶部浮光服从同一个 indicator 风格：`accent / success / warning / danger` 分别复用 `undergo / completed / near / passed` 的基础 indicator 色；与其他 Tab 统一使用低浓度整屏渐变与 `SCREEN` 混合，保留染色范围并减少灰脏感。
- 用户可在“显示与个性化 → 界面显示”关闭顶部浮光；开关默认开启并持久化，切换后即时淡入淡出。
- 根层先把当前 Tab、清单 tone 与主题解析为单一颜色，再传给浮光组件；颜色改变时旧色与新色进行约 420ms 交叉淡化。
- 新增任务或习惯完成后必须显式刷新对应列表并重新发布语义快照，不能只依赖同步事件间接刷新。
- 移除任务与习惯列表顶部的 `SemanticDashboardHero` 状态卡片，页面不再因浮光额外增加一张摘要卡。
- 全应用只允许 `Index` 根级容器渲染一个顶部浮光；`MainHomePage` 只向根层发布清单语义 tone 与滚动进度，不再自行绘制浮光。
- 根级浮光必须扩展到系统顶部安全区之后，并保持不拦截点击。
- 清单页浮光使用当前任务/习惯可见范围的语义 tone；多彩主题下清单 Tab 图标与文字使用 `theme.brand`，其他 Tab 的浮光及 Tab 选中色使用各自模块色；其余主题使用当前主题既有 Tab/brand 规则，不再被 `useWhiteGlow` 条件隐藏。
- Tab 切换时只更换根级浮光颜色；清单列表滚动时继续按归一化进度收缩，其他 Tab 使用展开态。
- 浮光位于基础背景之上、`HdsNavigation` 与全部可交互内容之下；根容器固定顶部对齐，浮光本身和宿主均使用 `HitTestMode.None`，不得遮盖卡片或阻塞点击。
